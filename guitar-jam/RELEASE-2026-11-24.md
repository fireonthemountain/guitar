# Guitar practice release

The release combines the existing curriculum and practice-gains work with a compatible
build stack, assessment-driven practice, Dead 90 progress integration, accurate example
tempo, and safer cloud synchronization. The source work remains preserved on
`redesign/2026-11-practice-gains` at `c706868`; the review branch starts from main
`53a7840` and excludes the unrelated ESP32 demo.

## Verification

Use Node 26 (`nvm use` in this directory), then:

```sh
npm ci --no-audit --no-fund
npm test -- --maxWorkers=3
npm run validate:curriculum
npm run build
npm audit
```

The automated checks cover existing progress, assessment routing, legacy Dead 90
integration, microphone suggestion lifecycle, playback subdivision, aborted requests,
concurrent edits, recovery copies and simulated two-device round trips. They do not
establish real-instrument accuracy, real-iPhone behavior or a deployed database connection.

The compatible dependency refresh clears the high and critical audit records. Two moderate
advisories remain as four dependency alerts in the PWA build chain:
`vite-plugin-pwa → workbox-build → glob → minimatch`. The local call is
`workbox-build/build/lib/get-file-details.js` using `globSync` with the repository's build
patterns from `vite.config.js`; browser practice data does not supply those patterns.
The records remain open for an upstream compatible fix. `npm audit` therefore exits 1;
no forced downgrade or suppression is applied. The advisories are
[glob cancellation](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) and
[minimatch amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249).

## Cloud setup and recovery

The production sync endpoint returned HTTP 503 with `no database linked` during preparation.
Link the intended Redis database to the Vercel guitar project and apply its environment
configuration to the environments being tested. The function accepts either
`KV_REST_API_URL`/`KV_REST_API_TOKEN` or `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN`.
Never put these values in the repository or browser. Review the provider's selected plan
before creating resources. Deploy and test the candidate before changing production.

Pair devices using the same private sync code in Progress → Cloud Sync. The built-in
endpoint returns an ETag; uploads compare it atomically in Redis. A stale upload returns
409 without replacing the cloud copy. Older open clients without this protocol receive
428 and need to refresh after deployment. The old Cloudflare KV worker retains its
one-active-device limitation; its preflight check cannot provide an atomic write guarantee.

If copies differ, automatic replacement stops. Cloud Sync offers downloads of the saved
device and cloud snapshots, and a choice of which copy to continue with. Recovery downloads
remain accessible after the choice. Use the complete Progress export for a whole-app backup;
the older Dead 90 export remains course-only. Keep exported backups outside this public app.

Dead 90's separate browser state is imported after main-store recovery and retained in its
old key as a compatibility copy. New course edits join the same saved progress blob as
Train, so they can participate in full export/import and synchronization.

## Real guitar validation

Use a supported secure origin and headphones for the scoring click. For each row, play
30 seconds of the single-string exercise at the stated quarter-note tempo with four notes
per click. Compare the heard note positions with the intended sequence and recorded playback;
counts alone can hide missed and doubled notes.

| Instrument and sound | Tempo | Notes correctly matched | Extra detections | Result |
|---|---:|---|---|---|
| Acoustic | 60 BPM | Not measured | Not measured | Owner check pending |
| Acoustic | 100 BPM | Not measured | Not measured | Owner check pending |
| Clean electric | 60 BPM | Not measured | Not measured | Owner check pending |
| Clean electric | 100 BPM | Not measured | Not measured | Owner check pending |
| Normal electric gain | 60 BPM | Not measured | Not measured | Owner check pending |
| Normal electric gain | 100 BPM | Not measured | Not measured | Owner check pending |

Proposed acceptance: at least 90% correctly matched onsets and at most 5% extra detections
in the supported quiet-room setup. These are targets, not current accuracy measurements.
Record the input device, room and gain setting. A sparse, old or excess note stream now
withholds timing suggestions; stopping the mic, stopping the click or changing tempo
clears the previous suggestion. Detection thresholds have not been tuned without real playing.

Also check that an uneven take grades below a controlled take; calibrate speaker-to-mic
delay separately; test whole-step bends above/on/below target and deliberate slow/fast
vibrato. Microphone feedback remains optional and manual grading stays available.

## iPhone and persistence checks

1. Use Safari and the installed PWA in portrait and landscape. Scroll the tab and collapse
   the browser toolbar: Clean, Shaky, Missed, Click and Next must remain reachable.
2. Allow the microphone deliberately, then check record/playback and first-tap audio unlock.
   Denied permission must leave manual practice usable.
3. Check both course routes. A failed technique assessment should put its matching exercise
   first, with a reason, once per daily technique block. Complete a rep and return to Today.
4. Export progress before pairing. With the database linked, make three Mac → iPhone → Mac
   round trips using a test record. Refresh each device and verify the same progress.
5. Disconnect briefly, make a change and reconnect. Local progress must survive and its
   pending state must remain visible until acknowledged.
6. Make independent changes on two devices before syncing. Both copies must remain
   recoverable; deliberately choose the copy to continue with.
7. Complete two 20–30 minute sessions on separate days, one acoustic and one electric.
   Retain the export and note any blocking issue or misleading feedback.

The initial release is ready for normal use after these checks. The full fingerstyle
course, broad dead-code cleanup and extra exercises remain follow-ups. Only reviewed
lessons can be published; private source PDFs and page images remain excluded.

## Release and rollback

Review the combined candidate and its CI results before merging: main auto-deploys to the
live Vercel site. Record the approved commit and preview URL in the handoff. A rollback
restores the previous app/API deployment; retain progress exports and recovery snapshots.
Do not delete or rewrite stored progress as part of rollback. No home-lab, Finance, ski,
or mingle-bingo work is part of this release.
